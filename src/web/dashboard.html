DNS rewrites

DomainAnswer

Local DNS records, answered before any filtering or recursion — so they win over blocklists and are never cached. An IPv4 answers A queries, anything else becomes a CNAME (its target resolved upstream and appended). IPv6 answers are not supported — the resolver is IPv4-only. *.domain covers the domain and every subdomain; one domain can hold several answers. Persisted across restarts.

DNS service

Start, stop, or move the resolver's listener without a restart — applied live and persisted (over config.toml [dns]). Any change here rebuilds the resolver, so the cache is cleared, but upstreams, rewrites and the settings below are kept.

Upstream servers

One per line (IPv4 only — the resolver doesn't speak IPv6): https://host/dns-query (DoH) · tls://host (DoT) · udp://ip / bare IP / tcp://ip (plain DNS).

Cache

Cached answers are clamped into the [min, max] TTL band. A resize keeps existing entries; changed TTLs apply to answers cached from now on.

Query log

The resolver is IPv4-only — AAAA queries are answered NODATA without resolving — so they are kept out of the live query log by default. Turn on to log them too. Applied live and persisted; metrics count AAAA queries either way.

ECH detection — probe whether each upstream returns ECH configs

Must be a domain that publishes an ECHConfigList, or every upstream reads as "no ECH". Leave blank to disable detection. Results appear in the ECH column of the DNS upstreams table on the Dashboard; each upstream is re-probed hourly.

Check domain — test a domain against the DNS filter without sending a query

Hostname rules only (||domain^), as the DNS resolver applies them — typed and $third-party options never match at this layer. To test a full URL the way the HTTP proxy sees it, use the Rule tester tab.

Proxy service

Start, stop, or move the proxy's listener without a restart — applied live and persisted. Rebinding drops connections currently using the old address.

Name resolution & privacy

The proxy resolves the hosts it connects to by querying this app's filtering DNS resolver like any other client — same filtering, rewrites, cache and upstreams (configured on the DNS → Settings tab) — never the container's system or LAN resolver. If the resolver is disabled, egress connections fail rather than leaking lookups to the system resolver.

Resolve the hosts the proxy dials over IPv4 only: send a Type A query and never a Type AAAA (type 28) one, and never open an IPv6 connection. On by default. Turn it off to also query AAAA and let the proxy connect over IPv6 when a host publishes one.

Read the target's ECH config from its HTTPS DNS record and negotiate Encrypted Client Hello on the outbound TLS connection, hiding the server name from the network. Requests whose connection used it are tagged [ECH] in the Requests log.

Rule tester — check a URL against the current rules without sending traffic

Scheme optional — host.com, host.com/path, or a bare path like /ads.js all work (paths are tested against a neutral host, so only host-agnostic rules match).

Type matters: EasyList rules are often restricted to a resource type (a browser sends script for /ads.js). If a URL tests blocked here but still loads, that request isn't reaching the proxy (e.g. an OS/app that bypasses the proxy).

Statistics & logs

The statistics window lives in memory and restarts with the process. Request and DNS query records append to request-log.jsonl / query-log.jsonl next to the blocklists; when a file gets older than the rotation period it is moved to its .old sibling (replacing the previous one), so records are kept for one to two rotation periods.
